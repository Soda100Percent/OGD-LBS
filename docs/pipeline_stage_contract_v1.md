## 管线与维度

γ 验收从缓存 source_data1 开始：
source_data1 → step02 → step03 → step04。

每个结果维度仅归属于一个阶段。
缓存使用本阶段与全部前置阶段的累计维度，并核验所需产物能力。
当前 profile、历史默认解释和 param/value 身份兼容政策不在本次迁移。
没有未分配维度，不代表旧 data4 profile 已补齐累计维度。
未知历史行为不能通过猜测默认值获得命中。

最终目标是结果导向逆向裁剪，再正向按资源组阶段屏障执行。
命中结果后不补算本次不需要的祖先缓存。
V1 先实现单阶段入口；缺直接上游时阻塞，阶段切换保留人工确认。

## γ 验收协议

gamma=[0.1,0.3,0.5,0.7,0.9]。
使用 keep_sum_one，剩余 alpha:beta 保持 0.5:0.3。
完整有效参数由实验展开层一次计算并冻结。
论文默认 gamma=0.2 不在五点内，不自动增加第六点或高亮其他值为默认。

## 阶段执行与资源

每阶段绑定一个 .sh，接收 task_request.json 路径。
结果参数、输入产物、执行资源和运行身份分开记录。
阶段脚本不自行查池、换输入、执行下游或写中央结果池。

data2/data3 每实例18 GiB，data4每实例4 GiB。
每实例默认8逻辑CPU时间配额，脚本内部默认8进程。
资源额度不是算法峰值保证；须覆盖最终指标阶段进行实测。
CPU时间配额、物理核心数和内部进程数不能混同。

## 资源组与阶段屏障

实验提交显式选择 Intel 或 AMD 组。
同组最多一个活动计算阶段；后续实验排队。
不同组可以并行，也可以分别处于不同阶段。
主机不得同时分配给两个活动组，不自动跨组借用主机。
硬件组默认是执行记录，不是隐式结果维度。

## 完整产物与缓存能力

所有计算阶段默认保存完整最终输出、业务summary、参数、输入来源和文件清单。
data4保存完整优化后骨架、动画、全部mesh、metrics及history。
规划的标准payload路径为 payload/data4；报告读取适配必须同步实现。

完整最终输出不等于开启 save_intermediate。
不重复保存上游payload，使用artifact引用记录来源。
退出码为零并通过业务验证后，才能发布完成标记。

旧data4指标/history记录可继续用于原有报告。
不能据此认定完整模型payload已保存，或直接赋予optimized_model能力。
完整模型缺失时，该记录不足以满足要求完整模型的缓存查询。
回填必须从明确、可验证的原始输出执行独立操作，本次不回填或重算。
